> **수신**: 플랫폼 구현 세션 · **발신**: 플랫폼 트랙 (2026-10-19 · 사용자 확정)
> **근거**: `docs/명세.md` §2 원칙 · §3 구조 · §4 데이터 창구 · §5 그래프 화면의 [P1] 표시
> **시스템 기준 커밋**: `playjae0/ontology_system` `4af5505` — 읽기 전용(고치지 않는다 · 불러오지 않는다)
> **시간**: 두 시간 안. 넘을 것 같으면 아래 완료판정 순서대로 된 데까지 하고 멈춰서 남은 것을 보고한다.

## 0. 개발 환경 — 시스템은 받아서 실행만 한다

```bash
git clone https://github.com/playjae0/ontology_system.git ../ontology_system
git -C ../ontology_system checkout 4af5505
cd ../ontology_system
python run.py init --fresh --all        # 시스템 mock 상태(state_mock/ — 시스템 .gitignore 안)
python run.py all                       # 표본 문서 인입 — 그래프가 생긴다
```

- 파이썬 의존이 없다고 멈추면 그 문면대로 설치한다(예: `pip install openpyxl python-pptx`). 시스템 파일은 고치지 않는다.
- 이 그래프는 **mock 표본**이다. 화면이 도는지 확인하는 데만 쓰고, 숫자를 품질 근거로 쓰지 않는다.
- 플랫폼은 `python run.py --system ../ontology_system --allow-mock`으로 띄운다(개발 세션만 `--allow-mock`).

## 2. 만들 것

### ① 백엔드 — `run.py` · `backend/` · `requirements.txt`

- **`run.py`**: 명세 §3.1 순서 그대로. 옵션 `--system <폴더>`(필수) · `--port N`(기본 8800 · 차 있으면 다음 빈 포트) · `--allow-mock` · `--no-browser`.
  플랫폼 서버는 `127.0.0.1`에만 연다.
- **`backend/system_server.py`** — 시스템과 닿는 유일한 자리:
  - 시스템 데이터 서버를 자식 프로세스로 띄운다: `[sys.executable, "-u", "run.py", "viewer", "--no-browser", "--port", <빈 포트>]` ·
    작업 폴더 = 시스템 폴더 · 환경은 그대로 물려주고 `PYTHONIOENCODING=utf-8`만 더한다(명세 §3.1-1) · 표준 오류도 함께 읽고 UTF-8로 푼다.
  - 출력에서 `[viewer] http://127.0.0.1:<포트>/` 줄을 찾아 주소를 읽는다(그 앞에 다른 줄이 나올 수 있다).
    120초 안에 못 읽거나 자식이 끝나면 그때까지의 출력을 그대로 보이고 멈춘다(사내 그래프가 크면 주소를 찍기 전에 그래프를 읽는 시간이 걸린다).
  - 끝날 때(Ctrl+C · SIGTERM · 오류) 자식을 끈다 — 남는 프로세스 0.
  - 중계: `GET /api/*`·`/raw/*`를 그대로 넘긴다(응답 코드·본문·Content-Type 그대로 · 쿼리 문자열과 경로의 퍼센트 인코딩 그대로).
    시간 제한은 `/api/query` 10분, 나머지 60초. 자식이 죽었으면 502 `{"error": "시스템 서버가 꺼졌다 — 플랫폼을 다시 켜라"}`.
  - 시스템 서버의 출력은 콘솔과 `logs/platform_<날짜>.log`에 같이 남긴다.
  - 시스템 커밋: 시스템 폴더에 `.git`이 있으면 `git rev-parse --short HEAD`, 없으면 `null`(사내는 zip으로 받은 폴더일 수 있다).
- **`backend/contract.py`** — 명세 §4 칸 목록과 `check(주소 종류, 응답) → 빠진 칸 목록` 하나.
  - 켤 때 `health`·`graph`를 확인한다 — 빠지면 그 목록을 찍고 멈춘다(종료 코드 ≠ 0).
  - 그 밖의 주소는 중계 응답마다 확인하고, 빠진 칸이 있으면 응답 헤더 `X-Platform-Missing: <칸,칸>`로 화면에 알린다(본문은 고치지 않는다).
  - **오류 응답(HTTP ≥ 400 또는 본문에 `error`)은 확인하지 않는다** — 서버 문면이 그대로 화면에 가야 한다.
- **mock 거부**: `/api/health`의 `mode`가 `"mock"`이고 `--allow-mock`이 없으면
  「시스템이 mock 모드로 떠 있다 — 사내 데이터가 아니다. 개발 중이면 --allow-mock」을 찍고 멈춘다(시스템 서버도 끈다 · 종료 코드 ≠ 0).
- **`backend/app.py`**: `/`·정적 파일(`frontend/dist`) · 중계 · `GET /platform/status` →
  `{system_url, system_dir, system_commit, mode, allow_mock, missing: {주소: [칸…]}, started_at}`. 로직은 위 두 파일에.
- **`requirements.txt`**: fastapi · uvicorn — 판을 고정한다.

### ② 화면 — `frontend/`

- React + TypeScript + Vite. 그래프 판을 고정한다: `sigma@3.0.3` · `graphology@0.26.0` · `@sigma/edge-curve@3.1.0` · `@sigma/node-border@3.0.0`.
  **`@sigma/node-border`의 최신(4.x)은 sigma 4를 요구해 설치가 깨진다 — 3.0.0을 쓴다.** sigma의 최신 문서·예제는 4판이니 3판 기준으로 본다. 외부 주소 0.
- 명세 §5의 **[P1]** 전부: 배치(5.1) · 그림(5.2) · 관계 토글·찾기·연결 없는 노드 숨김(5.3) · 노드 상세의 그래프 칸(5.5) · 머리 줄과 mock 띠(5.6).
- **힘 계산**(명세 §5.1): 시스템 뷰어의 `cli/viewer/static/force_worker.js`와 `layout.js`의 워커 다루는 부분(`forceStart`·`forcePause`·`forcePin`)을 옮겨 쓴다.
  - 끄는 동안: 그 점에 `pin` 메시지를 계속 보낸다(손을 따라간다) → 워커가 돌고 있으면 이웃이 따라온다.
  - 워커가 반복을 다 돌아 쉰 상태에서 끌기 시작하면(`resume`은 반복이 남았을 때만 돈다): 지금 좌표를 시작 자리로, 고정한 점들을 `fixed`로 `start`를 다시 보낸다(다시 데우기 · 반복 수는 가결정).
  - 시작 자리는 명세 §5.1 규칙(골격 노드는 `roots`에서 골격 노드끼리의 엣지로 넓이 우선 · 나머지는 `anchor.host` 둘레) — **관계 이름을 코드에 넣지 않는다**
    (시스템 뷰어 `layout.js`의 시작 자리는 `"part_of"`를 박아 쓰므로 그대로 옮기지 않는다).
- 응답 헤더 `X-Platform-Missing`이 오면 그 화면에 「시스템이 바뀌어 화면이 못 따라간다 — 빠진 칸: …」 카드.
- 확인용 손잡이(읽기 전용): `window.__platform = { graph, visible(), layout: { running, iterations } }` —
  `graph`는 그리는 graphology 인스턴스, `visible()`은 지금 화면에 보이는(숨김 제외) 노드·엣지 id 목록. verify 스크립트가 좌표와 수를 읽는 데만 쓴다.

### ③ 빌드·안내

- `frontend/dist`를 커밋한다(사내에는 Node가 없다).
- `README.md`: 사내 실행법 — Python만 · `pip install -r requirements.txt` · `python run.py --system <시스템 폴더>` · 시스템이 mock이면 열리지 않는다.
- `.gitignore`: `logs/` · `node_modules/` · `__pycache__/` (`frontend/dist`는 넣는다).

## 3. 완료판정 — 전부 실행으로 (`verify/`에 스크립트)

- ⓐ **명령 하나**: `python run.py --system ../ontology_system --allow-mock --no-browser` → 시스템 서버와 플랫폼이 뜨고 플랫폼 주소가 찍힌다.
  Ctrl+C(또는 SIGTERM) 뒤 시스템 서버 프로세스가 남지 않는다(`ps`로 확인).
- ⓑ **mock 거부**: `--allow-mock` 없이 → 거부 문면 · 종료 코드 ≠ 0 · 시스템 서버도 꺼져 있다.
- ⓒ **칸 확인**: `contract.check`가 칸을 하나 뺀 응답(시험 안의 dict)에서 그 칸을 정확히 내고, 정상 응답에서는 빈 목록을 낸다.
  오류 응답(`{"error": …}` · 상태 400)은 확인하지 않는다.
- ⓓ **화면 = 서버**: `visible()`의 노드 = `/api/graph`의 노드 중 `anchor`에 있는 것 · 엣지 = 양 끝이 다 보이는 엣지(관계 토글 전부 켠 상태).
- ⓔ **퍼진다**: 배치가 쉰 뒤 연결된 쌍의 평균 거리 < 연결 안 된 쌍의 평균 거리 × 0.5.
- ⓕ **당기면 따라온다**: 이웃이 있는 노드 하나를 Playwright 마우스로 끌어 옮기면, 2초 안에 그 이웃들의 평균 이동이 끈 거리의 10% 이상이고
  끈 방향 쪽이다(이동 벡터와 끈 방향의 내적 > 0). 배치가 쉰 뒤에 끌어도 같다(다시 데우기). 놓은 노드는 놓은 자리에 남는다.
- ⓖ **층 건너는 엣지**: 관계 토글을 전부 꺼도 `cross` 엣지는 보이고, 다른 선(곡선 · 다른 색)이다.
- ⓗ **찾기는 강조만**: 이름으로 찾으면 걸린 노드가 강조되고, 찾기 전후 모든 노드 좌표가 그대로다(배치를 다시 하지 않았다).
- ⓘ **노드 상세**: 노드를 누르면 상세의 인접 엣지 수 = `/api/graph`에서 그 노드를 끝으로 가진 엣지 수 · 그래프 칸 값 = 그 노드의 응답 값.
- ⓙ **쓰기 0**: 화면을 쓰고 난 뒤 시스템 상태 폴더의 `data/`·`registry/`·`layers/` 아래 파일 해시가 그대로다 · 시스템 폴더 `git status --porcelain` 빈 출력.
  (`work/` 아래는 시스템 서버가 스스로 만드는 파생물·로그라 대상이 아니다.)
- ⓚ **외부 요청 0**: 화면을 여는 동안 브라우저가 보낸 요청이 전부 플랫폼 주소(`127.0.0.1:<플랫폼 포트>`)로 간다(Playwright 요청 기록).
  (번들 안의 `http://www.w3.org/…` 같은 이름공간 글자는 요청이 아니라 대상이 아니다.)
- ⓛ **화면 캡처 하나**(개발 표본 — 「mock」 표시): 배치가 쉰 전체 그래프. 보고에 경로를 적는다.

⓪ 수치 문턱(ⓔ 0.5 · ⓕ 10%)은 **동작 확인용**이다 — 품질 목표가 아니다. 플랫폼 트랙이 개발 표본에서 잰 값(연결/비연결 거리 비 0.268 ·
이웃 17개인 노드를 펼친 폭의 30%만큼 옮겨 고정하면 30회 뒤 이웃 평균 이동이 옮긴 거리의 40%)에서 여유를 두고 잡았다.
