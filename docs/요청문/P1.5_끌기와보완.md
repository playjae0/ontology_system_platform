## 2. 만들 것

### ① 끌기 배치 (명세 §5.1 [P1.5])

**워커** `frontend/src/graph/force_worker.js` — 플랫폼 사본이라 고쳐도 된다.
- `start` 메시지의 선택 칸 `anchor: { k: number[] }` — 노드마다 용수철 세기(`x`·`y`와 같은 순서). 있으면 시작 좌표를 「제자리」로 잡고,
  반복마다 중력 다음에 `DX[i] -= k[i] * M[i] * (X[i] - AX[i])` · `DY[i] -= k[i] * M[i] * (Y[i] - AY[i])`. **없으면 지금과 한 글자도 다르지 않게 돈다**(전체 배치는 바뀌지 않는다).
- 새 메시지 `cool {iters}` — 반복 상한을 「지금 반복 수 + iters」로 바꾸고, 쉬고 있으면 다시 돈다.
- 머리 주석의 「(133행 · 고치지 않고 그대로)」를 「위 두 가지만 더했다」로 바꾼다. `force.ts` 머리의 「워커는 시스템 것 그대로다」도 같이 고친다.

**`force.ts`** (ForceLayout)
- `startDrag(…)`: `setGraph`에 준 엣지로 끄는 노드에서 넓이 우선 홉 수 h를 센다 — **엣지 방향은 보지 않는다(양쪽으로)**.
  k(h) = k₀ (h ≤ 2) · min(k₀ × 3^(h − 2), 1) (h ≥ 3) · 끄는 노드에서 닿지 않는 노드는 이 끌기 동안 `fixed`에 넣는다.
  지금 좌표 · `fixed`(놓아 둔 점 + 끄는 점 + 닿지 않는 점) · `anchor` · **반복 상한 없음**으로 `start`를 보낸다.
  **상한 1을 빼지 않는다** — 플랫폼 트랙 실측: 30단 공정 사슬의 첫 단을 끌면 상한 없이는 먼 노드가 끈 거리의 수천만 배로 날아가고, 상한 1이면 끈 거리 안에 머문다(mock은 홉이 짧아 이 문제를 못 잡는다).
- `release()`: `cool {iters: 300}`.
- 상태에 배치 종류 `kind: "layout" | "drag"`(전체 배치 / 끌기 배치)를 둔다.
- 상수(k₀ 다섯 단 · 홉마다 3배 · 상한 1 · 식힘 300)는 이 파일 머리 한 자리에 둔다.

**`view.ts`** 끌기 손짓 — 누르기·끌기 가르기(P-15)는 그대로.
- 처음 움직일 때: 전체 배치가 돌고 있으면(`kind === "layout"`이고 running) 지금처럼 그 점에 `pin`만 · 사람이 「멈춤」을 눌렀으면 지금처럼 그 점만 옮긴다 ·
  그 밖(쉼 · 끌기 배치 중 · 식히는 중)이면 `startDrag` — 그 순간 좌표가 새 제자리다.
- `pin`만 하던 손짓이 이어지는 동안 전체 배치가 끝나면(running이 거짓이 되면) 다음 움직임에서 `startDrag`로 넘어간다(그 순간 좌표가 제자리).
- 움직이는 동안 `pin`(지금처럼). 손을 떼면 **이 손짓이 `startDrag`로 끌기 배치를 시작했을 때만** `release()` — 「멈춤」 상태에서 그 점만 옮긴 손짓은 식히지 않는다(사람이 누른 멈춤을 풀지 않는다).
  놓은 점은 지금처럼 그 자리에 고정.
- `rewarm`·`REWARM_ITER`(P-05)는 없앤다 — DECISIONS P-05에 「P1.5에서 끌기 배치로 바뀜」을 적는다.

**밀대 「끌 때 따라오는 범위」** — 배치 칸의 간격 밀대 아래 · 좁게 ↔ 넓게 5단 = k₀ `0.04 · 0.03 · 0.02 · 0.015 · 0.01` · 기본 가운데(0.02) ·
`data-testid="follow"` · 다음 끌기부터 적용.

**머리 줄 힘 상태** — 끌기 배치는 「끌기」, 손을 뗀 뒤는 「식힘 n/300」(전체 배치 표시는 그대로). 반복 상한이 없다고 큰 수를 보이지 않는다.

**확인용 손잡이** — `window.__platform = { graph, sigma, visible(), layout: { running, iterations, kind } }`(`kind`를 더한다). P2도 이 판을 쓴다.

**기본값을 mock으로 고르지 않는다.** k₀·배수·상한·식힘 횟수는 위 값 그대로 둔다. 보기 편한 값은 사용자가 사내 그래프에서 밀대로 고르고, 플랫폼 트랙이 기본값을 바꾼다.

### ② P1 보완 — mock이 사내 쪽에 드러나지 않게

- **mock 거부 문면**(명세 §3.1-3) — `--allow-mock` 안내를 뺀다. 네 줄, 종료 코드 2 그대로:
  ```
  [platform] 시스템이 실데이터가 아니라 mock 모드로 떴다 — 화면을 열지 않는다
  [platform]   이 셸의 ONTO_HOME: <값 | 없음>
  [platform]   시스템이 읽은 상태 폴더: <`/api/health`의 home>
  [platform]   셸 설정(~/.zshrc 등)의 ONTO_HOME과 그 폴더의 llm.json을 확인한다
  ```
- **도움말**: `run.py --help`에 `--allow-mock`이 보이지 않게 한다(`help=argparse.SUPPRESS` · 옵션은 그대로 동작).
- **README**
  - 사내 실행 절: 리눅스 경로로 · **시스템 CLI를 쓰는 그 파이썬(가상환경)에** `pip install -r requirements.txt`(플랫폼은 자기를 실행한 파이썬으로 시스템 서버를 띄운다) ·
    셸 설정 별칭 예 `echo "alias onto-platform='<시스템 CLI의 파이썬 경로> <플랫폼 폴더>/run.py --system <시스템 코드 폴더>'" >> ~/.zshrc`(파이썬 경로는 시스템 CLI를 치던 셸에서 `which python`) ·
    머리 줄 「상태」가 시스템 `doctor` 첫 줄의 상태 폴더와 같은지 확인 · Ctrl+C 뒤 `pgrep -af "run.py viewer"`가 빈 출력 ·
    종료 코드는 「0 정상 · 1 시스템 서버를 못 띄움 · 2 시스템이 실데이터로 뜨지 않음 · 3 칸 빠짐」.
    **이 절에는 대소문자 무관하게 「mock」이 나오지 않는다** — 시스템 설정은 `ONTO_HOME`과 `$ONTO_HOME/llm.json`으로만 말한다.
  - 맨 아래 「개발 세션 전용」 절: `--allow-mock` · verify 스크립트. 옵션 표의 `--allow-mock` 줄도 이 절로 옮긴다.
- **P1 확인 스크립트 고침**
  - `p1_process.py` ⓑ: 거부 문면 대조를 새 네 줄로 바꾼다.
  - `p1_screen.py` ⓕ-도는 중: 노드를 누른 채(아직 움직이지 않고) 「다시 배치」를 키보드로 누르고(포커스 + Enter) 곧바로 움직인다.
    판정은 첫 움직임 직후에 `kind === "layout"`이고 running일 때만 한다 — 아니면 다시(다섯 번까지) · 끝내 못 잡으면 FAIL.
  - `p1_screen.py` ⓕ-쉰 뒤는 뺀다(이제 끌기 배치라 §3 ⓐ·ⓓ가 잰다) · ⓕ-고정은 첫 노드만 잰다.

## 3. 완료판정 — 전부 실행으로 (`verify/p15_drag.py` 하나 + 고친 P1 스크립트)

홉 수는 `window.__platform.graph`에서 끄는 노드부터 넓이 우선으로 세고, **엣지 방향은 보지 않는다**(graphology `forEachNeighbor` — 들어오고 나가는 쪽 모두).
「이동」은 끌기 직전 좌표와 쉰 뒤 좌표의 거리, 비율은 끈 노드의 이동 대비다.

- ⓐ **연결된 노드가 따라온다**: 배치가 쉰 뒤 연결이 가장 많은 노드를 캔버스 폭의 25%만큼 끌어 놓고 쉴 때까지 기다린다 →
  1홉 평균 ≥ 30% · 1홉 > 2홉 > 4홉 이상(4홉 이상 노드가 없으면 3홉 이상) · 4홉 이상 평균 ≤ 20%.
- ⓑ **끌지 않으면 흐르지 않는다**: 쉰 뒤 노드를 누른 채 2px만 움직여 2초 머문 뒤 놓고 쉴 때까지 → 끈 노드를 뺀 모든 노드의 평균 이동 < 그래프 반경(무게중심에서 잰 RMS 거리)의 1%.
- ⓒ **누르는 동안 계속 돈다**: 끈 채 3초 머무는 동안 `kind === "drag"` · `running` 참 · 1초 간격으로 두 번 잰 `iterations`가 는다.
- ⓓ **놓으면 쉰다**: 놓은 뒤 10초 안에 `running`이 거짓 · 끈 노드는 놓은 자리(어긋남 0) · 그 전에 놓아 둔 노드도 그대로(어긋남 0).
- ⓔ **전체 배치 중 끌기는 그대로**: §2②의 ⓕ-도는 중과 같은 방법(누른 채 「다시 배치」 → 곧바로 움직임 · 첫 움직임 직후 `kind === "layout"`·running이 아니면 다시, 다섯 번까지)으로 끈다 →
  그 점만 고정되고 전체 배치가 `force.iterations`까지 돈다 · 놓은 자리 그대로.
- ⓕ **밀대가 듣는다**: 「다시 배치」로 같은 시작에서 두 번 — 「좁게」와 「넓게」로 같은 노드를 같은 거리만큼 끌면 1홉 평균 이동이 넓게 > 좁게(워커가 결정적이라 시작이 같다).
- ⓖ **mock 거부 문면**: `--allow-mock` 없이 켜면 종료 코드 2 · 출력에 「ONTO_HOME」 줄과 「상태 폴더」 줄이 있고 「--allow-mock」 글자가 없다 · `python run.py --help` 출력에도 「allow-mock」이 없다.
- ⓗ **README 사내 절**: 「개발 세션 전용」 절 앞까지 대소문자 무관하게 「mock」 글자가 없다.
- ⓘ **회귀**: 고친 P1 확인 스크립트 셋 전부 PASS — 쓰기 0 · 외부 요청 0 포함.
- ⓙ **화면 캡처 하나**(개발 표본 — 「mock」 표시): 허브를 끌어 놓은 뒤. 보고에 경로를 적는다.

⓪ 수치 문턱은 **동작 확인용**이다 — 품질 목표가 아니다. 플랫폼 트랙이 같은 워커 코드로 mock 그래프의 허브를 끌어 잰 값(시작 자리·끄는 거리는 화면과 다르다):
지금 방식 1홉 98% · 4홉 이상 61% → 끌기 배치(k₀ 0.02) 1홉 72% · 2홉 43% · 3홉 14% · 4홉 이상 6% · 1홉은 좁게(0.04) 62~65% · 넓게(0.01) 79~82%.
**mock 표본의 개수를 세는 어서션은 만들지 않는다**(CLAUDE.md §5).
