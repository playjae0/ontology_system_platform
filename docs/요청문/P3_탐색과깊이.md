# P3 요청문 — 탐색(골격 먼저 · 카테고리별 깊이 · 펼치기 · 질의 끌어오기) · 연결 수 크기 · 그리기 부하

> **수신**: 플랫폼 구현 세션 · **발신**: 플랫폼 트랙 (2026-11-17 · 사용자 확정) · **P2(PR #3) 병합 뒤**
> **근거**: `docs/명세.md` §5.4 탐색 · §5.1 「보이는 노드가 바뀔 때」 · §5.2 크기 · §5.3 찾기 · §5.5 [P3] · §5.6 그리기 · §5.7 그리기 부하 · §6.1 겹쳐 보기 · §3.3 사내(자기 PC 브라우저)
> **시스템 기준 커밋**: `playjae0/ontology_system` `5ae4444`(B211 병합) — 읽기 전용. 플랫폼 트랙이 2026-11-17에 이 커밋의 mock에서 P1·P2 확인이 전부 통과함을 봤다.
> **시간**: 두 시간 안. 넘을 것 같으면 완료판정 순서대로 된 데까지 하고 멈춰서 보고한다.

**이 회차가 하는 것.** 사내 그래프(노드 약 1,500 · 엣지 약 4,000)에서 시스템 뷰어가 멈췄다. 플랫폼은 전부를 한 번에 그리지 않고 골격에서 시작해
카테고리별 깊이 · 펼치기 · 질의 끌어오기로 보이는 노드를 늘린다(Neo4j 브라우저처럼). 사내 PC는 따로 꽂는 그래픽 카드가 없어(내장 그래픽만) 그리기가
소프트웨어일 수 있다 — 그래도 끌기가 손을 따라오게 그리기 부하를 줄이고, 그리기 장치를 머리 줄에 보인다. 노드 크기는 연결 수로 바꾼다.

## 0. 개발 환경

- 시스템: `git -C ../ontology_system fetch && git -C ../ontology_system checkout 5ae4444` → 시스템 폴더에서 `python run.py init --fresh --all && python run.py all`(mock 표본 · 73노드).
- **합성 그래프**(완료판정 ⓐ~ⓙ의 일부): `verify/p3_synth.py`(이 회차에 만든다)가 시스템 폴더를 임시 폴더로 복사하고(`.git` 제외 — `USE_MOCK=1`은 `ONTO_HOME`을
  무시하고 시스템 폴더의 `state_mock/`을 읽으므로 폴더째 복사한다) 그 `state_mock/data/<층>/graph.json`에 노드를 더해 N개로 만든다. 끝나면 임시 폴더를 지운다.
  - 만드는 법: mock 그래프의 골격 밖 노드를 본으로 돌려 가며 복제한다 — 카테고리 · 층은 본 그대로 · 이름 `<본 이름>·합성<i>` · provenance `SYN#R<i>` · 26자 id.
    본의 엣지마다 같은 관계 · 같은 방향 · 같은 층 그래프에 하나씩 — 상대는 본의 상대와 **같은 카테고리** 노드 중 Zipf(s = 0.8)로 골라 몇 노드에 몰리게 한다.
    같은 (src, rel, dst)는 한 벌(시스템 B180) · 두 끝이 같은 엣지 0. 층·카테고리·관계 이름을 스크립트에 적지 않는다(데이터에서 읽는다).
  - 플랫폼 트랙이 같은 꼴로 만든 2,000노드는 엣지 4,279 · 연결 수 최대 299였다. **합성 그래프의 수는 동작 확인용이다**(품질 근거 아님 · CLAUDE.md §3) — 화면에 「합성」을 적는다.
- 브라우저: 머리 없는 Chromium(`p1_screen.py`의 `GL_ARGS`) — 그리기가 소프트웨어(SwiftShader)라 §5.7의 소프트웨어 갈래가 그대로 재진다.

## 2. 만들 것

- **① 보이는 노드 — 한 함수**(명세 §5.4): 골격(`seed`) ∪ 카테고리별 깊이(`anchor[id].hops` ≤ 그 카테고리의 깊이) ∪ 펼친 노드 ∪ 질의로 끌어온 노드, 그리고 그 노드들의 골격까지의 길
  (`anchor.host`를 골격까지). 닻이 없는 노드는 밖. 지금 `nodeShown`을 쓰는 자리(그리기 · 머리 줄 수 · 범례 · 찾기 수 · 화면에 없는 노드 수)가 전부 이 함수를 쓴다.
- **② 카테고리별 깊이 표**(왼쪽 칸 맨 위): 카테고리마다 한 줄 — 「0 · 1 · 2 · 3 · 전부」와 「그려지는 수 / 전체 수」 · 「골격만」 · 「전체」.
  **첫 화면**: 닻이 있는 노드 수 N > `explore_threshold` 또는 (그리기 소프트웨어 · N > 500)이면 「골격만」, 아니면 「전체」. 500은 상수 한 자리(플랫폼 트랙이 정한 값 그대로).
- **③ 펼치기**: `doubleClickNode`(`preventSigmaDefault`로 확대를 막는다) · 노드 상세의 「여기서 펼치기」 → 중계 `/api/neighbors/<id>` → 닻이 있는 이웃을 더한다.
  왼쪽 칸 칩 「펼침: <이름> +n」 · 칩 ×(그 펼침만 뺀다) · 「모두 접기」. 찾기 칸: 걸린 수 「보임 n · 숨김 m」 · Enter → 첫 결과(보이는 것 먼저 · 이름 순)에서 펼치기.
- **④ 질의 끌어오기**(명세 §5.4 · §6.1): 겹쳐 보기가 생기면 칠할 노드 중 안 보이는 것(닻 있음)을 칩 하나 「질의: <질문 앞 20자> +n」으로 더한다 ·
  새 질의가 칩을 바꾼다 · 겹쳐 보기를 지우면 칩도 빠진다 · 서버에 더 묻지 않는다.
- **⑤ 보이는 노드가 바뀔 때의 배치**(명세 §5.1): 그리는 그래프에 노드를 더하고 빼고(sigma는 그대로 하나) 힘 배치도 보이는 노드로 다시 정한다.
  새 노드는 닻 `host`(보이면 · 아니면 펼친 노드) 둘레에서 출발 · 이미 있던 노드는 끌기 배치의 제자리 용수철(평형에서 시작 — P1.6)로 붙잡고 식힘(`COOL_ITER`)만큼.
  새 노드가 이미 있던 노드보다 많으면 보이는 노드로 전체 배치. 빠지는 노드는 빠지기만. 「다시 배치」는 보이는 노드만.
  **「전체」의 노드 순서는 지금과 같게**(서버 순서) — 전체 배치 좌표가 바뀌지 않아야 한다(ⓚ).
- **⑥ 크기 = 연결 수**(명세 §5.2): `/api/graph` 엣지 전부로 한 번 센다 · 반지름 = 최소 + (최대 − 최소) × √(연결 수 ÷ 최대 연결 수) · 최소·최대 픽셀은 `style.ts` 한 자리(가결정).
  라벨 글자 크기는 tier 그대로 · 크기 범례를 「크기 = 연결 수」(작은 · 가운데 · 최대 n)로 · 노드 상세에 「연결 수 n · 화면에 m」.
- **⑦ 그리기 부하**(명세 §5.7):
  - 프레임 합치기 — `applyFrame`은 받은 좌표를 두고 `requestAnimationFrame`에서 가장 최근 것 하나만 적용한다.
  - 끄는 동안 마우스 아래 노드 찾기를 끈다 — sigma에 끄는 설정이 없다. 플랫폼 트랙 시험에서는 끌기를 시작할 때 마우스 잡이의 `mousemove` 듣개
    (sigma의 `activeListeners.handleMove`)를 떼고 놓을 때 다시 붙였다(sigma 3.0.3 고정 · 그 자리에 주석). 다른 길이 있으면 가결정.
  - 그리기 장치 — `WEBGL_debug_renderer_info`로 이름을 읽어 머리 줄 「그리기 GPU · 소프트웨어 · —」(툴팁에 이름).
  - 같은 엣지 id — 처음 것만 그리고 왼쪽 칸에 「같은 엣지 n개는 한 번만 그렸다」.
  - 그리는 그래프에는 보이는 노드만(①).
- **⑧ README 사내 절**(명세 §3.3): 예시 경로(`~/onto/…`) 대신 자리표시 + 찾는 법(파이썬 = 시스템 CLI 셸의 `which python` · 플랫폼 폴더 · 시스템 코드 폴더 = 각자 `run.py`가 있는 폴더 —
  상태 폴더 `$ONTO_HOME`과 다르다) · 별칭에 `--no-browser` · 자기 PC 브라우저로 여는 법(VS Code가 「플랫폼 주소」 줄의 포트를 넘겨 준다 — `[system]` 줄 주소는 열지 않는다 ·
  그 밖의 SSH는 `ssh -L 8800:127.0.0.1:8800 <서버>` 뒤 PC 브라우저에서 `http://127.0.0.1:8800/`) · 머리 줄 「그리기」의 뜻 · 화면 절의 크기·탐색 설명.
- **⑨ 확인용 손잡이**(읽기 전용)에 더한다: `renderer: {name, software}` · `explore: {depths, chips}`(지금 값의 사본).
- **장부**: DECISIONS P-38부터 · PROGRESS 맨 위.

## 3. 완료판정 — 전부 실행으로 (`verify/p3_explore.py` 하나 · 합성은 `verify/p3_synth.py`)

확인용 손잡이로 잰다. 좌표를 비교하는 판정은 배치가 쉰 좌표를 쓴다(P2 §3 그대로).

- ⓐ **첫 화면**: mock(73) → 「전체」(보이는 노드 = 닻 있는 노드) · 합성 2,000 → 「골격만」(보이는 노드 = 골격 노드) ·
  합성 800 → 「골격만」(문턱 아래지만 머리 없는 Chromium은 소프트웨어 — 머리 줄 「그리기 소프트웨어」 · 툴팁의 장치 이름을 보고에).
- ⓑ **깊이 표**(합성 2,000): 골격 밖 노드가 가장 많은 카테고리를 1로 → 보이는 노드 = 골격 ∪ {그 카테고리 · hops ≤ 1} ∪ 그들의 골격까지의 길(`/api/graph`로 따로 셈 · 같아야 한다) ·
  표의 수 = 그린 수 · 「전체」 → 닻 있는 노드 전부 · 「골격만」 → 골격만.
- ⓒ **끌기 한 걸음**(합성 2,000 · 「전체」 · 연결 수가 가장 많은 노드를 8px씩 10걸음 · 걸음마다 다음 그리기까지 기다림): 평균이 착수 전(전제 12)의 1/3 이하 — 전 · 후 둘 다 보고.
- ⓓ **펼치기**(합성 2,000 · 「골격만」): 이웃이 가장 많은 골격 노드를 두 번 누름 → 더해진 노드 = `/api/neighbors` 중 닻 있는 것 ∪ 그들의 골격까지의 길 · 카메라 비율 그대로(확대 안 됨) ·
  칩 「펼침: … +n」의 n = 더해진 수 · 칩 × → 펼치기 전 집합. Enter 펼치기: 숨은 노드 이름으로 찾기 → 「보임 0 · 숨김 k」 · Enter → 그 노드와 이웃이 보인다.
- ⓔ **펼칠 때 배치**(ⓓ의 펼치기): 펼친 노드에서 4홉 이상인 기존 노드의 평균 이동 < 그래프 반경(RMS)의 1% · 펼친 뒤 보이는 노드의 연결 쌍 평균 거리 ÷ 비연결 쌍 평균 < 0.5(P1 ⓔ 잣대).
- ⓕ **질의 끌어오기**(합성 2,000 · 「골격만」 · 시스템 `tests/fixtures/queries.json`의 첫 문항): 칠할 노드 중 닻 있는 것이 전부 보인다 · 칩 하나 ·
  둘째 문항 → 칩이 바뀐다(여전히 하나) · 겹쳐 보기 지우기 → 칩이 빠지고 질의 전 집합 · 끌어오는 동안 `/api/neighbors`·`/api/graph` 요청 0.
- ⓖ **크기**: 연결 수가 큰 노드가 작게 그려지는 쌍 0(같은 수는 같은 크기) · 크기가 최소·최대 픽셀 안 · 관계를 전부 끄거나 깊이를 바꿔도 노드마다 크기 그대로.
- ⓗ **같은 엣지**: `/api/graph` 응답을 가로채(Playwright `route`) 엣지 하나를 복제해 넣으면 그래프가 그려지고 「같은 엣지 1개는 한 번만 그렸다」가 뜬다.
- ⓘ **README**: 사내 절에 `~/onto` 0 · `--no-browser`가 별칭 줄에 · 포트 전달 두 길이 있다 · 「개발 세션 전용」 절 앞까지 「mock」 0(P1.5 규칙 그대로).
- ⓙ **회귀**: P1 확인 셋 · `p2_query.py` 전부 PASS(mock은 「전체」로 열린다).
- ⓚ **전체 배치 그대로**: `python verify/p16_drag.py --ref <전제 13의 파일>` → ⓐ~ⓔ 전부 PASS(「다시 배치」 뒤 쉰 좌표가 같다).
- ⓛ **쓰기 0 · 외부 요청 0**: P1 ⓙ·ⓚ와 같은 확인(합성 임시 폴더는 시스템 폴더 밖 · 끝나면 지운다).
- ⓜ **화면 캡처 둘**(「합성」 표시): 「골격만」에서 하나 펼친 화면 · 질의를 끌어온 화면. 보고에 경로.
