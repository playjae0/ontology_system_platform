# 플랫폼 명세 — 온톨로지 시스템 플랫폼

> **지위**: 플랫폼의 정본이다(2026-10-19 플랫폼 트랙에서 사용자 확정). 정본 자리는 레포 `ontology_system_platform`의 `docs/명세.md`이고,
> claude.ai 프로젝트 `플랫폼/명세.md`는 같은 내용의 사본이다.
> **옛 문서와의 관계**: 프로젝트의 `플랫폼안건/`(2026-08~09)은 논의 기록이다. 이 명세와 다르면 이 명세가 이긴다.
> **시스템과의 관계**: 시스템이 실제로 하는 일은 시스템(`playjae0/ontology_system`)이 정본이다. 플랫폼은 시스템을 바꾸지 않는다.
> **고치는 사람**: 이 문서는 플랫폼 트랙(claude.ai 대화)이 고친다. 구현 세션은 바꿀 문장을 마감 보고에 제안한다.

---

## 1. 목적과 지금 단계

- **목적**: 시스템의 기능 전부를 화면으로 쓰게 한다(노코드화). 지금 CLI·파일을 손으로 다루는 일을 화면 조작으로 옮긴다.
- **사용자**: 운영자 한 사람(사용자 본인). 로그인 없음 — 플랫폼은 `127.0.0.1`로만 연다.
- **지금 단계는 뷰어와 질의다.** 그래프는 지금처럼 시스템 CLI로 만들고, 플랫폼은 만들어진 그래프를 보고 질의한다. 인입·등록·수정은 다음 단계다(§7).
- **회차**: P1 = 뼈대와 그래프 화면 · P2 = 질의·문서·연결 현황(노드 상세의 근거 포함). 요청문은 `docs/요청문/`.
  회차 하나는 두 시간 안이다 — 그래서 §5에서 「다음」으로 표시한 것은 P1·P2에 넣지 않았다.

## 2. 원칙

1. **시스템 코드를 고치지 않는다.** 시스템 레포는 읽기 전용이다.
2. **시스템 코드를 불러오지(import) 않는다.** 시스템과는 두 길로만 잇는다 — 데이터 서버(HTTP GET · 보기·질의)와 명령 실행(나중 · 인입·등록·수정).
   시스템 내부는 회차마다 움직인다(예: B78-2가 core 파일을 파트 폴더로 옮기며 옛 경로를 남기지 않았다). 바깥으로 드러난 창구(데이터 주소·명령)만 쓴다.
   시스템 뷰어의 **그리기 코드**(`cli/viewer/static/*.js`)는 복사해 플랫폼 코드로 삼을 수 있다 — 불러오기가 아니라 옮겨 와서 플랫폼이 소유한다. 계산 코드는 옮기지 않는다.
3. **계산은 시스템이 한다.** 플랫폼은 그리기·입력·실행 순서만 맡는다. 질의·판정·병합·닻·trace를 다시 계산하지 않는다.
4. **플랫폼은 자기 데이터를 갖지 않는다.** 그래프·문서·대장의 진짜는 시스템 상태 폴더(`$ONTO_HOME`)에 있다. 이번 단계는 쓰기 0이다.
5. **mock은 없다.** 플랫폼 코드에 mock 모드·가짜 데이터·표본 파일을 두지 않는다. 시스템이 mock으로 떠 있으면 화면을 열지 않는다(개발 세션만 `--allow-mock`).
6. **조용히 깨지지 않는다.** 시스템 응답에 화면이 쓰는 칸이 빠지면 무엇이 빠졌는지 화면에 말한다. 시스템 오류 문면은 고치지 않고 그대로 보인다.
7. **층 어휘를 코드에 넣지 않는다.** 층·카테고리·관계 이름은 데이터에서 읽는다. 시스템 어휘(노드 `status`의 `seed`·`obsolete`, `tier`의 `main`·`sub`·`detail`, 엣지 `cross`)는 써도 된다.
8. **사내 데이터는 레포에 올리지 않는다** — 문서·그래프·화면 캡처 포함.
9. **판정은 실행으로 한다.** 개발(mock)에서는 동작을 확인하고, 보기 편한지는 사용자가 사내 실제 그래프로 판정한다.

## 3. 구조

```
브라우저 — 플랫폼 화면 하나 (http://127.0.0.1:<플랫폼 포트>/)
   │
플랫폼 백엔드 (이 레포 · FastAPI)
   ├ 화면 파일(frontend/dist)을 내준다
   ├ /api/* · /raw/* 를 시스템 데이터 서버로 그대로 넘긴다 (GET)
   ├ 켤 때·응답마다 화면이 쓰는 칸을 확인한다 (contract)
   └ /platform/status — 플랫폼 쪽 상태
   │ HTTP 127.0.0.1                         │ (나중) subprocess
   ▼                                        ▼
시스템 데이터 서버                          시스템 명령 실행
python -u run.py viewer --no-browser --port N   python run.py <명령> … (인입·등록·수정)
(시스템 폴더에서 · 화면은 쓰지 않는다 ·
 켜질 때 질의 벡터를 배경에서 준비하고 계속 떠 있다)
   │                                        │
   └────────── $ONTO_HOME (그래프·문서·대장 — 시스템이 쓴다) ──────────┘
```

### 3.1 기동 — 명령 하나

`python run.py --system <시스템 폴더> [--port N] [--allow-mock] [--no-browser]`

1. 시스템 데이터 서버를 자식 프로세스로 띄운다 — 작업 폴더는 시스템 폴더, 파이썬은 플랫폼과 같은 것에 `-u`(출력 버퍼 없이).
   환경은 플랫폼을 켠 셸 그대로 물려주고(`ONTO_HOME`·`USE_MOCK`·게이트웨이 설정을 바꾸지 않는다) `PYTHONIOENCODING=utf-8` 하나만 더한다
   — 시스템 출력에 한글·「—」가 있어, 파이프 인코딩이 cp949인 환경에서 시스템 서버가 죽지 않게 한다(시스템 `doctor.py`가 권하는 값과 같다). 출력은 UTF-8로 읽는다.
2. 시스템 서버의 출력(표준 출력 + 표준 오류)에서 `[viewer] http://127.0.0.1:<포트>/` 줄을 찾아 주소를 읽는다.
   그 앞에 다른 줄이 나올 수 있다. 포트가 차 있으면 시스템이 다음 빈 포트를 고른다. 주소를 못 읽고 시스템 서버가 끝나면 그 출력을 그대로 보이고 멈춘다.
3. `/api/health`로 모드를 본다 — `mode`가 `"mock"`이고 `--allow-mock`이 없으면 거부하고 멈춘다(시스템 서버도 끈다).
4. `/api/health`·`/api/graph`의 칸을 확인한다(§4) — 빠지면 빠진 칸을 찍고 멈춘다.
5. 플랫폼 주소를 찍고(기본으로 브라우저를 연다), 끝날 때(Ctrl+C·오류) 시스템 서버도 끈다 — 남는 프로세스 0.
6. 쓰는 중에 시스템 서버가 죽으면 중계는 502와 `{"error": "시스템 서버가 꺼졌다 — 플랫폼을 다시 켜라"}`를 낸다.

### 3.3 사내 설치

- Python만 있으면 된다: `pip install -r requirements.txt` → `python run.py --system <시스템 코드 폴더>`.
- 폴더는 시스템 코드 폴더 옆에 둔다. 상태 폴더(`$ONTO_HOME`)는 시스템 설정 그대로다.
- 그래프 엔진은 MIT(sigma.js·graphology). Neo4j NVL은 쓰지 않는다(§8 결정 기록).

## 4. 시스템 데이터 창구 — 화면이 쓰는 칸

기준: 시스템 커밋 `4af5505`(2026-10-19 실측). 시스템 서버는 `127.0.0.1`에만 열리고 GET만 있다.

| 주소 | 주는 것 | 화면이 쓰는 칸 |
|---|---|---|
| `/api/health` | 상태 루트·모드·등록 수·층·문서 수 | `home` · `mode` · `layers` · `docs` · `doc_types` |
| `/api/graph` | 전 층 그래프 + 닻 · 연결 없는 노드 · 골격 뿌리 · 탐색 문턱 · 힘 상수 | 위: `nodes` · `edges` · `layers` · `rels` · `anchor` · `detached` · `roots` · `explore_threshold` · `force`<br>노드: `id` · `name` · `category` · `layer` · `status` · `tier` · `polarity` · `made_by` · `aliases`(개수) · `attrs`(개수) · `docs` · `prov` · `queue`<br>엣지: `id` · `src` · `dst` · `rel` · `layer` · `status` · `prov` · `cross` |
| `/api/node/<id>` | 노드 상세의 근거 | `id` · `name` · `anchor_path` · `evidence` · `evidence_total` · `landed` |
| `/api/neighbors/<id>` | 1홉 이웃 | `id` · `neighbors` |
| `/api/doc/<doc_id>` | 문서 대장 행·판정 집계·만든 노드·청크·원본 상대 경로 | `doc_id` · `registry` · `raw_rel` · `rows` · `tally` · `sheet_roles` · `nodes` · `chunks` |
| `/raw/<경로>` | 원본 파일(상태 폴더 `raw/` 아래만) | — |
| `/api/funnel` | 문서 깔때기 + 열린 orphan 행 | `keys` · `rows` · `total` · `orphans` · `정의` |
| `/api/status` | 질의 진행·벡터 준비 | `query` · `vectors` · `stages` · `line` |
| `/api/query?q=` | 질의 답 묶음 — CLI `query --json`과 같은 함수 | `question` · `path` · `linked_nodes` · `facts` · `chunks` · `doc_search` · `records` · `records_total` · `truncated` · `note` · `trace` · (있을 때만) `related`<br>`trace`: `intent` · `linking` · `link_stage` · `hops` · `facts` · `collection` · `doc_search` · `answer` · `miss` |

읽을 때 알아 둘 것:

- `/api/graph`에는 **병합된 노드와 폐기(`obsolete`)된 노드가 아예 오지 않는다**(시스템 `is_live`). 그래서 「obsolete 보이기」는 두지 않는다.
- `/api/graph`의 `aliases`·`attrs`는 **개수**다 — 별칭 글자와 속성 값은 없다. 별칭으로 찾기는 지금 못 한다(필요하면 시스템 회차로 요청).
- `prov`는 provenance **앞 4개를 쉼표로 이은 글자**다(전부가 아니다). 노드가 나온 문서 목록은 `docs`(목록)로 본다 — `docs`의 `"seed"`는 골격이라 문서가 아니다(`/api/doc/seed`는 404).
- `anchor`는 노드 id → `{anchor, host, hops}`(닻이 있는 노드만 — 골격 노드는 host가 자기 자신) · `detached`는 `{edgeless, island}` · `roots`는 골격 뿌리 id 목록.
- 질의의 `related`는 「관련 원문」 청크가 있을 때만 온다. 노드 근거 청크의 본문은 `chunks`·`related`·`doc_search`에서 `chunk_id`로 찾는다.
- **칸 확인**: 위 칸 목록은 `backend/contract.py` 한 곳에 둔다. 켤 때 `health`·`graph`를 확인하고, 그 밖의 주소는 응답을 받을 때마다 확인한다.
  빠진 칸이 있으면 화면에 「시스템이 바뀌어 화면이 못 따라간다 — 빠진 칸: …」을 띄운다. 시스템이 새로 더한 칸은 무시한다(깨지지 않는다).
  **오류 응답(HTTP ≥ 400 또는 본문에 `error`)은 칸을 확인하지 않는다** — 그때는 서버 문면을 그대로 보인다.

## 5. 화면 — 그래프

각 절 끝의 [P1]·[P2]·[다음]은 어느 회차가 만드는지다.

### 5.1 배치 — Neo4j처럼 [P1]

- **힘 배치 하나다.** 퍼지고(원·격자 모양으로 굳지 않는다), 노드를 끌면 연결된 노드가 힘으로 따라온다.
- 힘 계산은 **웹 워커**에서 한다 — 화면이 멈추지 않는다. 안정되면 쉬고, 끌면 다시 돈다.
- 힘 계산은 시스템 뷰어의 `force_worker.js`(ForceAtlas2 계열 · Barnes–Hut · 결정적)를 옮겨 쓴다. 돌고 있는 중에 점을 고정하는 `pin` 메시지가 있어,
  끄는 동안 그 점이 손을 따라가고 이웃이 따라온다. 반복을 다 돌아 쉰 뒤에 끌면 지금 자리에서 다시 시작한다(다시 데우기).
  (graphology의 정식 ForceAtlas2 워커는 시작할 때만 위치·고정을 읽어서 이 동작에 우회가 필요하다 — 그래서 고르지 않았다.)
- **시작 자리는 결정적이다**(같은 데이터 → 같은 시작) — 골격 노드(`status` = `seed`)는 `roots`에서 골격 노드끼리의 엣지를 따라(관계 이름과 무관하게) 넓이 우선으로 줄을 세우고,
  나머지 노드는 닻(`anchor.host`) 둘레에서 출발한다. 열 때마다 비슷한 그림이 되게 하려는 것이고, 똑같을 필요는 없다.
- 놓은 노드는 그 자리에 고정한다(그 세션 동안). 「다시 배치」를 누르면 고정이 풀리고 시작 자리부터 다시 돈다.
- 조절: 간격(퍼짐) · 멈춤/이어서 · 다시 배치. 힘 상수의 기본값은 `/api/graph`의 `force`(시스템 손잡이 `viewer_force`)에서 읽는다.

### 5.2 그림 [P1]

- **크기**: tier 계단(main > sub > detail > 골격 밖). 골격 노드(`status` = `seed`)는 테두리로 구분한다.
- **라벨**: 이름 사슬의 끝 조각(`a::b::c` → `c`). 마우스를 올린 점·고른 점·찾기에 걸린 점은 전체 이름. 「전체 이름」 토글.
- **엣지**: 방향이 보이게 화살표. 관계 이름은 확대했을 때. **층을 건너는 엣지(`cross`)는 관계 토글과 무관하게 언제나 그리고, 한눈에 다른 선(곡선 + 다른 색)으로 그린다** — 이 시스템의 존재 이유가 층 사이 연결이다.
- **색**: 축 하나를 골라 그 값으로 칠한다(`layer` · `category` · `status` · `tier` · `polarity` · `made_by` — 기본 `category`). 색은 값에서 결정적으로 만든다. 범례.
- **글꼴**: 시스템 글꼴(맑은 고딕·Noto Sans KR 등) — 외부 폰트를 내려받지 않는다.
- **테마**: 밝은 테마 하나.

### 5.3 거르기·찾기

- 관계 토글 [P1] · 찾기(이름·id — **강조만 한다**, 다시 배치하지 않는다) [P1].
- 기본으로 `anchor`에 없는 노드(연결 없는 노드)는 숨긴다 [P1]. 「연결 없는 노드 보이기」 토글(수 표시) [다음].
- 축 값으로 거르기(layer·category 등의 값 고르기) [다음].

### 5.4 탐색 — 노드가 많으면 골격부터 [다음]

- 노드 수가 `explore_threshold`(시스템 손잡이 `viewer_explore_threshold` · 기본 1,500)를 넘으면 골격 뿌리(`roots`)부터 열고,
  클릭으로 1홉씩 펼친다(`/api/neighbors/<id>`). 빵부스러기 · 접기 · 전체 보기. 그래프가 작아도 노드 상세의 「여기서 펼치기」로 들어갈 수 있다.
- 그 전까지는 전체를 그린다 — 힘 계산이 웹 워커라 수천 개에서도 화면은 멈추지 않는다(시스템 뷰어 B114가 노드 5,904개로 확인).

### 5.5 노드 상세

- [P1] 그래프 노드 칸: layer · category · status · tier · polarity · made_by · 별칭 수 · 속성 수 · 큐 · id · provenance(`prov` 글자 그대로) · 인접 엣지(누르면 그 노드로).
- [P2] `/api/node/<id>`의 근거 청크·닻까지의 길·문서마다 붙은 자리 · 나온 문서(`docs` — `seed` 제외)를 누르면 문서 패널(§6.2) · 「이 노드로 질문」(§6.1).

### 5.6 머리 줄 [P1]

- 시스템 모드 · 상태 루트 · 시스템 커밋(모르면 폴더 이름) · 층 · 문서 수 · 보이는 노드/엣지 수 · 힘 상태 · 질의 벡터 준비 줄(`/api/status`의 `line`).
- 시스템이 mock이면(개발 세션) 맨 위에 「시스템 mock 모드 — 개발용 데이터」 띠가 늘 보인다.

## 6. 화면 — 질의·문서·연결 현황 [P2]

### 6.1 질의

- 질문 → `/api/query?q=`. 묻는 동안 `/api/status`를 짧은 간격으로 읽어 단계(벡터 준비 › 링킹 › 확장 › 수집 › 답변)와 경과 초를 보인다.
  (개발 mock에서는 질의가 수십 ms에 끝나 중간 단계가 안 보일 수 있다 — 끝난 뒤 지난 단계 표시와 「끝」만 확인되고, 중간 단계는 사내에서 본다.)
- **칸 일곱** — 시스템 뷰어와 같은 묶음이고, 응답에 있는 것만 싣는다(새 계산 0):
  - ⓐ 링킹: 노드 칩(사전 링킹과 「임베딩 후보 + LLM 선별」은 모양을 다르게 · 선별은 점수·이유)
  - ⓑ 확장 경로: 홉마다 엣지(`trace.hops[].edges`)
  - ⓒ 그래프 사실: 답에 쓴 것 표시(`trace.facts[].used`)
  - ⓓ 노드 근거 청크: 상한에서 잘린 것 회색(`kept=false`) · 쓴 것 표시
  - ⓔ 문서 검색: 점수(임베딩·BM25) · 노드 근거와 겹침 · 쓴 것
  - ⓕ 짧은 답: `trace.answer.text` · 모드 배지(`trace.answer.mode`) · 줄 수 · 쓴 근거 수
  - ⓖ 노드 원 레코드: `records`(가공 없이) · 링킹 칩을 누르면 그 노드의 레코드가 펼쳐진다
- **그래프 위에 겹쳐 보기**: 사전 링킹 노드 · LLM이 고른 노드 · 확장으로 닿은 노드를 서로 다른 색으로, 경로 엣지는 굵게.
  `trace.linking`·`trace.hops`에 적힌 것만 칠한다(경로를 추정하지 않는다). 한 노드가 링킹과 확장 둘 다에 있으면 **링킹 색**이다(시스템 뷰어와 같다).
  배치는 다시 하지 않는다. 칠할 노드가 화면에 숨겨져 있으면 「화면에 없는 노드 n개」로 알린다.
- 경로 배지(`path`) · 의도(`trace.intent`) · 미스(`trace.miss`) · 잘림(`truncated`) 알림 · LLM 배지(모드 · 링킹 사전/선별 수 · 답변).
- 노드 상세의 「이 노드로 질문」 — 질문 칸에 이름을 넣고, 전송은 사람이 한다.
- 오류는 서버 문면 그대로 보인다(`{"error": …}` · HTTP ≥ 400).

### 6.2 문서

- 노드 상세의 나온 문서·청크 카드의 「원본」에서 연다: `/api/doc/<doc_id>` — 판정 집계(`tally`) · 대장 행 수(`rows`) · 만든 노드 · 시트 역할(있으면) · 청크.
- 원본 열기: `raw_rel`이 있으면 `/raw/<raw_rel>`, 없으면 「원본이 상태 폴더 raw/ 아래가 아니다」.

### 6.3 연결 현황

- `/api/funnel` — 문서마다 깔때기 표 + 합계 + 열린 orphan 행. 표 위에 정의 문장(`정의`).
