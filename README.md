# 온톨로지 시스템 플랫폼 (`ontology_system_platform`)

온톨로지 시스템(`playjae0/ontology_system`)을 화면으로 쓰게 하는 플랫폼이다. 지금 단계는 **보기**(그래프)다 —
그래프는 지금처럼 시스템 CLI로 만들고, 플랫폼은 만들어진 그래프를 본다. 정본 문서는 `docs/명세.md`다.

플랫폼은 시스템 코드를 고치지도 불러오지도 않는다. 시스템 폴더에서 시스템 데이터 서버(`run.py viewer`)를 자식으로 띄우고,
그 서버에 HTTP GET으로 묻는다. 시스템 상태 폴더(`$ONTO_HOME`)에는 아무것도 쓰지 않는다.

## 사내 실행

Python만 있으면 된다 — 화면은 이미 빌드되어 `frontend/dist`에 들어 있다(Node 불필요 · 외부 주소 0). 플랫폼 폴더는 시스템 코드 폴더 옆에 둔다.

아래 `<…>`는 자리표시다. 자기 경로를 이렇게 찾아 넣는다.

| 자리표시 | 찾는 법 |
|---|---|
| `<시스템 CLI의 파이썬>` | 시스템 CLI를 치던 셸에서 `which python` |
| `<플랫폼 폴더>` | 이 README와 `run.py`가 있는 폴더(그 폴더에서 `pwd`) |
| `<시스템 코드 폴더>` | 시스템의 `run.py`가 있는 폴더 — 상태 폴더 `$ONTO_HOME`과 다르다 |

**1. 시스템 CLI를 쓰는 그 파이썬(가상환경)에 설치한다.** 플랫폼은 자기를 실행한 파이썬으로 시스템 서버를 띄우므로, 다른 파이썬으로 켜면
시스템의 선택 의존(로컬 임베딩 등)이 없어 질의가 깨질 수 있다.

```bash
<시스템 CLI의 파이썬> -m pip install -r <플랫폼 폴더>/requirements.txt
```

**2. 셸 설정에 별칭 한 줄을 한 번 등록한다.** 파이썬도 경로로 박는다 — 가상환경을 켜지 않은 셸에서도 같은 파이썬이 되게.
서버에서 켜므로 브라우저는 열지 않는다(`--no-browser`) — 자기 PC 브라우저로 연다(아래 3).

```bash
echo "alias onto-platform='<시스템 CLI의 파이썬> <플랫폼 폴더>/run.py --system <시스템 코드 폴더> --no-browser'" >> ~/.zshrc
source ~/.zshrc
onto-platform
```

- 플랫폼 폴더 안에 경로 설정 파일을 두지 않는다(회차마다 폴더를 통째로 바꾸므로 함께 사라진다). 시스템 코드 폴더 이름을 바꿔 반입하면 이 한 줄도 고친다.
- 상태 폴더는 플랫폼이 모른다 — 켠 셸의 환경(`ONTO_HOME`)이 그대로 시스템 서버로 간다. 시스템 설정은 `$ONTO_HOME/llm.json`이다.

**3. 자기 PC 브라우저로 연다.** 플랫폼은 서버의 `127.0.0.1`에만 열리므로 포트를 PC로 넘겨 연다.

- VS Code로 서버에 접속했으면 — 콘솔의 「플랫폼 주소 — `http://127.0.0.1:<포트>/`」 줄의 포트를 VS Code가 넘겨 준다(알림의 「브라우저에서 열기」).
  `[system]`으로 시작하는 시스템 서버 주소 줄은 열지 않는다(플랫폼이 그 서버에 묻는다).
- 그 밖의 SSH면 — PC에서 `ssh -L <포트>:127.0.0.1:<포트> <서버>`로 접속한 채 PC 브라우저에서 `http://127.0.0.1:<포트>/`(기본 포트 8800).

**4. 켜진 뒤 확인한다.**

- 플랫폼 주소(`http://127.0.0.1:8800/` — 차 있으면 다음 빈 번호)가 찍힌다. `127.0.0.1`에만 열린다.
- 화면 머리 줄의 「상태」가 내 상태 폴더(`echo $ONTO_HOME`)와 같은지 본다 — 다르면 셸 설정(`~/.zshrc` 등)의 `ONTO_HOME`을 확인한다.
- 멈출 때는 Ctrl+C — 시스템 서버도 함께 꺼진다. 그 뒤 `pgrep -af "run.py viewer"`가 빈 출력이어야 한다.
- 시스템 서버의 출력은 콘솔(`[system] …`)과 플랫폼 폴더의 `logs/platform_<날짜>.log`에 같이 남는다.

| 옵션 | 뜻 |
|---|---|
| `--system <폴더>` | 시스템 코드 폴더(`run.py`가 있는 곳) — 필수 |
| `--port N` | 플랫폼 포트(기본 8800 · 차 있으면 다음 빈 번호) |
| `--no-browser` | 브라우저를 열지 않는다 |

종료 코드: **0** 정상 · **1** 시스템 서버를 못 띄움(그때까지의 출력을 그대로 보인다) · **2** 시스템이 실데이터로 뜨지 않음
(이 셸의 `ONTO_HOME`과 시스템이 읽은 상태 폴더를 찍는다 — 셸 설정의 `ONTO_HOME`과 그 폴더의 `llm.json`을 확인한다) · **3** 칸 빠짐(빠진 칸을 찍는다).

## 화면

- 그래프 — 힘 배치(웹 워커)로 퍼진다. 노드를 끌면 연결된 노드가 따라온다 — 가까울수록 많이, 멀수록 적게. 놓으면 그 자리에 고정된다(「다시 배치」가 푼다).
- **끌 때 따라오는 범위** 밀대(좁게 ↔ 넓게 5단) — 다음 끌기부터 적용된다. 사내 그래프에서 허브와 잎을 끌어 보며 보기 편한 단을 고른다.
- **탐색** — 큰 그래프는 한 번에 다 그리지 않는다. 골격에서 시작해 보이는 노드를 늘린다.
  - 왼쪽 칸 맨 위 **카테고리별 깊이 표** — 카테고리마다 「0 · 1 · 2 · 3 · 전부」와 「그려지는 수 / 전체 수」 · 「골격만」 · 「전체」.
    깊이는 가장 가까운 골격 노드까지의 홉 수(시스템이 준 값)이고, 깊은 노드는 골격까지의 길과 함께 보인다.
  - 첫 화면 — 연결 있는 노드가 시스템의 탐색 문턱을 넘거나, 그리기가 소프트웨어이고 500개를 넘으면 「골격만」으로 연다(아니면 「전체」).
  - **펼치기** — 노드를 두 번 누르거나 상세의 「여기서 펼치기」 → 그 노드의 이웃이 더해진다. 펼친 것은 칩(「펼침: 이름 +n」)으로 쌓이고,
    칩의 ×는 그 펼침만 뺀다 · 「모두 접기」.
  - 찾기는 안 보이는 노드도 찾는다(「보임 n · 숨김 m」) — Enter는 첫 결과(보이는 것 먼저 · 이름 순)에서 펼친다.
  - 질의를 하면 칠할 노드 중 안 보이는 것을 칩 하나(「질의: 질문 앞부분 +n」)로 끌어온다 — 겹쳐 보기를 지우면 칩도 빠진다.
  - 보이는 노드가 늘면 새 노드만 자리를 잡고 이미 있던 노드는 거의 그대로다(새 노드가 더 많으면 보이는 노드로 다시 배치).
- **크기 = 연결 수** — 원의 넓이가 연결 수에 비례한다(전체 엣지로 센다 — 토글·깊이로 바뀌지 않는다). 라벨 글자 크기는 tier 계단.
  골격 노드(`status` seed)는 테두리 · 층을 건너는 엣지는 보라 곡선(관계 토글과 무관하게 언제나). 같은 엣지가 두 번 오면 한 번만 그리고 왼쪽 칸에 알린다.
- 색 축(layer · category · status · tier · polarity · made_by) · 관계 토글 · 찾기(강조만) · 전체 이름 · 간격 · 멈춤/이어서(멈춘 동안 끌면 그 점만 옮긴다).
- 머리 줄 힘 상태 — 진행 · 쉼 · 멈춤 · 끌기 · 식힘 · 자리 잡기(보이는 노드가 늘 때).
- 머리 줄 **그리기** — GPU · 소프트웨어 · —(못 읽음). 툴팁에 WebGL 장치 이름. 「소프트웨어」면 그래픽 가속 없이 그리는 중이라
  노드가 많을수록 화면이 느리다 — 「골격만」에서 펼쳐 가며 보는 쪽이 낫다. 끄는 동안에는 마우스 아래 노드 찾기를 꺼서 손을 따라오게 했다.
- 노드를 누르면 오른쪽에 상세 — 그래프 칸 · 「여기서 펼치기」 · 연결 수(전체 · 화면에) · 인접 엣지(누르면 그 노드로 · 안 보이면 「화면에 없음」) ·
  나온 문서 · 닻까지의 길 · 근거 원문 · 붙은 자리 ·
  「이 노드로 질문」(질문 칸에 이름을 넣고 질의 탭으로 — 보내기는 직접).
- **질의** 탭 — 질문 → 상태 줄(단계 · 경과) · 링킹 · 확장 경로 · 그래프 사실 · 노드 근거 청크 · 문서 검색 · 짧은 답 · 노드 원 레코드.
  그래프 위에 겹쳐 칠한다(주황 = 사전 링킹 · 자주 = LLM 선별 · 파랑 = 확장으로 닿음 · 굵은 주황 선 = 확장 경로). 배치는 그대로다.
- 나온 문서·청크의 「원본(문서)」을 누르면 문서 패널(판정 집계 · 대장 행 수 · 만든 노드 · 청크 · 원본 열기).
- **연결 현황** 탭 — 문서마다 깔때기 표 · 합계 · 열린 orphan 행(표 위에 정의 문장).
- 시스템 응답에 화면이 쓰는 칸이 빠지면 「시스템이 바뀌어 화면이 못 따라간다 — 빠진 칸: …」 카드가 뜬다. 시스템 오류는 문면 그대로 뜬다.

배치: `run.py`(진입) · `backend/system_server.py`(시스템과 닿는 유일한 자리) · `backend/contract.py`(화면이 쓰는 칸) ·
`backend/app.py`(라우트) · `frontend/`(React + TypeScript + Vite · sigma.js 3 + graphology) · `verify/`(회차 확인).
장부: `PROGRESS.md`(마감 보고) · `DECISIONS.md`(가결정) · `BLOCKERS.md`(명세가 답하지 않는 곳).

## 개발 세션 전용

사내에서는 쓰지 않는다. 개발 세션은 사내 데이터를 볼 수 없어 시스템 mock 상태로 한다(mock으로 본 숫자는 품질 근거가 아니다).

| 옵션 | 뜻 |
|---|---|
| `--allow-mock` | 시스템이 mock 모드여도 화면을 연다(화면 맨 위에 mock 띠). 도움말(`--help`)에는 보이지 않는다 |

```bash
# 시스템(읽기 전용 — 고치지 않는다)
git clone https://github.com/playjae0/ontology_system.git ../ontology_system
git -C ../ontology_system checkout 5ae4444
(cd ../ontology_system && python run.py init --fresh --all && python run.py all)   # mock 표본 그래프

# 화면 빌드 (Node 22) — 산출 frontend/dist를 커밋한다
cd frontend && npm ci && npm run build && cd ..

python run.py --system ../ontology_system --allow-mock

# 확인 (Playwright Python — pip install playwright==1.56.0)
python verify/p1_process.py      # P1 ⓐ 명령 하나 · ⓑ 실데이터 아님 거부
python verify/p1_contract.py     # P1 ⓒ 칸 확인
python verify/p1_screen.py       # P1 ⓓ~ⓛ 화면
python verify/p15_drag.py        # P1.5 ⓐ~ⓙ 끌기 배치 · 거부 문면 · README · 회귀(위 셋을 함께 돌린다)
python verify/p16_drag.py --ref <파일>   # P1.6 ⓐ~ⓔ 끌기 평형(착수 전 --save-ref <파일>로 기준 좌표 저장 · ⓓ가 p15를 돌린다)
python verify/p2_query.py        # P2 ⓐ~ⓚ 질의 · 겹쳐 보기 · 노드 근거 · 문서 · 연결 현황
python verify/p3_synth.py --n 2000          # P3 합성 그래프(레포 밖 임시 폴더 · 끝나면 지운다 · 수는 동작 확인용)
python verify/p3_explore.py --only c        # P3 착수 전 ⓒ(끌기 한 걸음) — 2코어로 묶어 잰다: taskset -c 0,1 python …
python verify/p3_explore.py                 # P3 ⓐ~ⓜ(ⓒ는 --before <착수 전 평균 초>를 줄 때)
```

캡처는 `verify/captures/`에 남는다 — 전부 mock 표본이거나 합성 그래프(「합성」 띠)다.
